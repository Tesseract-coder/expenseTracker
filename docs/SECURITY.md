# Kharcha — Security review (Phase 6, 2026-11-06)

Scope: the Worker API, the email handler, the web app and PWA, storage (D1, R2, browser), dependencies and the Phase 6 additions (PDF import, backup/restore). Threat model: one owner whose data is sensitive. The attacker may be:

- a stranger on the internet;
- a malicious website the owner visits while logged in;
- someone who forges alert e-mails;
- a hand-crafted backup or statement file.

Status: **Pass**, with the items under _Fixed in this review_ applied and the residual risks below accepted.

## Fixed in this review

1. **CSRF on cookie-authenticated multipart upload**: `sameOrigin` middleware (tests in `test/api.test.ts`).
2. **Client-chosen content type on stored files**: the R2 `contentType` now comes from the extension, PDFs must start with `%PDF-`, and downloads stay `attachment` + `nosniff`.
3. **Backup restore could plant data the app chokes on**: JSON columns are validated on restore (a rule with an unsafe regex is refused), and a stored column mapping that doesn't parse is skipped instead of failing the import screen with a 500.
4. **Indexing**: `noindex` header and `robots.txt` (the app is private and behind Access).

## Accepted residual risks

- **Dev-only advisories:** esbuild ≤ 0.24.2 (dev-server CORS, via drizzle-kit's loader; no dev server runs), glob 9–14 and deepmerge (via workbox-build at build time) and minimatch < 11.0.1 (via eslint, ReDoS on patterns we write). None ship to the Worker or the browser. Revisit when the upstream packages update.
- **Forged alert e-mails:** envelope senders can be spoofed where SPF/DMARC isn't enforced upstream. Impact is limited to "Needs review" rows the owner can delete.
- **Half-finished restore:** if the browser closes mid-restore, the account holds partial data until the same file is restored again. The page shows a warning, and the restore is repeatable. Download a backup first (offered in the UI).
- **Backup file at rest:** a plain JSON file on the user's device. Encrypting it with a passphrase is possible future work.
- **Lighthouse "Content security policy" issue:** caused by Lighthouse's own injected scripts; a normal browser session logs no CSP violations.
